## Flagged

- **Real, pre-existing bug found in already-merged Lane C code:**
  `WorksheetEngine._aggregate_fuel()` has no guard for `fuel_records` not
  existing yet — on a genuinely fresh install where no receipt has ever
  been processed, `WorksheetEngine.build()` crashes with a raw
  `sqlite3.OperationalError` instead of the already-designed
  `InsufficientDataError`. Same bug class Lane D's own `queries.py` had
  (fixed earlier this session) — but this one lives in `worksheet.py`,
  which this package's own launch package explicitly forbids editing
  (a different, already-merged, already-signed-off lane). **Not fixed at
  the source.** Handled instead at the UI layer: `app.py`'s `/build`
  route catches the specific `sqlite3.OperationalError` and renders the
  same "no data yet" message `InsufficientDataError` would, with a
  regression test (`test_build_on_a_genuinely_fresh_install_does_not_crash`)
  proving it. A proper fix belongs in `worksheet.py` itself (a
  table-existence guard, matching Lane D's own fix) — a real candidate
  for a future "Fix Real Problems As They Appear" round, not silently
  patched around forever.
- `seal()`'s original implementation only caught `ApprovalNotYetGrantedError`
  — an unknown worksheet ID raised `package.py`'s own
  `WorksheetNotFoundError` uncaught, a raw 500. Caught during this
  session's own testing (not a pre-existing bug — introduced and fixed
  within this same build), now returns a clean 404, matching
  `worksheet_detail()`'s existing behavior for the same case.
- No direct nav link from the Shell's own dashboard to `/ifta` yet — the
  launch package's "Files to modify" list scoped only `shell/app.py`'s
  one mount, not the Shell's own nav template, so that wasn't touched.
  Mike can reach `/ifta` directly today; a dashboard link is a small,
  separate, low-risk follow-up if wanted.
