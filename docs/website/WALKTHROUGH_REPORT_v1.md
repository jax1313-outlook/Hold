## How this walkthrough was run

Same procedure as every prior lane and phase: Mike does not have a
terminal into this remote environment, so the build session executed
every command and showed the real, unedited output at each step. The
real interface under test was the Shell itself — every action below is a
real HTTP request against the actual running dev server
(`python -m dispatch.shell.app`), including requests that follow links
*generated by the mounted apps' own templates* rather than typed by
hand, since that's the one genuine technical risk this package carries
(`docs/website/DISPATCH_SHELL_LAUNCH_PACKAGE_v1.md` §10, risk 1).

## Sandbox used

A throwaway sandbox outside the git repository:
`/home/user/mike_walkthrough_shell/` (deleted after this walkthrough
completed). `tools/init_roots.py`, `tools/seed_library.py`, and

## Step 1 — The dashboard on a genuinely fresh install

`GET /` against a database that had never been touched:

```
HTTP status: 200
Open queue item(s): 0 · In Pilot Inbox: 0 · Fuel/Receipts/RateCons/POD/ELD/Misc: 0 each
```

No crash on first load — exactly the class of bug ("no such table" on a
brand-new database) that a Lane D build session found and fixed earlier
in this project; the Shell inherits that fix for free by calling
Reports' own `create_app()` unmodified.

## Step 2 — A realistic drop, real success and real failure on the same run

Three files dropped into `DispatchPilot\Inbox`: a clean fuel-card CSV, a
CSV with a wrong declared total (a real, honest mistake — the same class
of error Lane C's and the Pilot's own walkthroughs have each exercised
before), and a rate confirmation. `POST /pilot/process` — the real
button:

```
Receipts:
  fuel_card_export.csv -> Fuel
  statement_export.csv -> quarantined / held for review, see Queue
Held for review:
  RateCon_BigState_Load91.pdf -> RateCons (rate confirmation)
```

Both outcomes rendered clearly on the same page — success and failure
side by side, neither one hidden.

## Step 3 — Following a real link generated by Queue's own unmodified template

The dashboard's "Open queue item(s): 2" card was clicked through to
`/queue/`, which listed both real items with real
`/queue/items/<id>` links — generated by Queue's own `index.html`,
completely unmodified, resolving correctly under the `/queue` mount
prefix. Followed one:

```
<h2>Line quarantined (sum_mismatch): Diesel fuel</h2>
```

Resolved it exactly as Mike would after reviewing the corrected export
tool: `POST /queue/items/<id>/resolve` with `decided_by=human:mike` and
a real note → `302`.
